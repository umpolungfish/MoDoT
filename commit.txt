Local inference on the GPU, and ob3ects in the legal glyph alphabet

Two faults in the --ob3ect / --provider local path.

GPU. The local candle provider fell to CPU because the binary was built without
the cuda feature and CUDA_VISIBLE_DEVICES was empty, which hides every card. The
binary is rebuilt --features local,cuda for the RTX 3060 (sm_86), and the ask
wrapper now sets the cuda runtime on the loader path and pins the 3060 — under
PCI_BUS_ID the 2080 SUPER (sm_75) is index 0 and the 3060 index 1, and exposing
only the sm_86 card means any device the binary selects is the right one. The
auto-rebuild branch now carries --features local,cuda so a missing binary
rebuilds with GPU instead of silently dropping it. Local runs at ~29 tok/s.

Glyphs. The ob3ect design path emitted text opcode names (VINIT, FSPLIT) and its
reference prompt still showed the retired forms ◇ ● + × ¬ =. opcode_glyph maps
each name to its legal glyph (⊢ ⊣ > < ⋈ ⊙ ∈ ∋ ⊤ ⊥ ⊞ ◻); phase_1 entries, the
sequence steps, and a glyph word now carry symbols. The reference prompt shows
the legal glyphs, and the step parser reads ∈ ∋ ⊤ ⊥ ◻ ⋈ alongside the old forms
so stored words still load. A regenerated cuboid ob3ect renders ⊢∈⊤<⋈∋⊞◻ with
zero retired glyphs.
