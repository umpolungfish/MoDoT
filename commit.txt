cl9nk: the agent had the tool and not the caveat

Access and knowledge were already there — cl9nk is a first-class TOOL with the
right framing, it is in the allowed verb list, the handler shells the catalog-native
Python navigator, and it returns real output. Verified end to end.

What was missing is that there are TWO cl9nk implementations and the agent was
never told. This tool runs the Python navigator; `kernel cl9nk` runs the kernel's
own. Their distances come from different metrics with different ceilings: the
kernel reports d(L8,L9)=1.7596, the Python variant tops out near 3.46, and
CL9NK_ASCENT.md records 5.63 from a third. The kernel's own output already carries
that warning; the agent's tool description did not, so an agent could read one
number, quote it against a document written from another, and have no way to know.

None of the three refutes the others. Added to the description, with the rule that
follows from it: say which you ran. Also restated that a structural expression this
returns is never hand-derived.
