Colour and separation in the output, and nothing in the pipe

Several verbs print thirty lines with no mark of where one ends and the next
begins, which is unreadable the moment two run in sequence. Each now opens with a
ruled header carrying the verb and its subject, and the words that decide a
result — CYCLIC, INSULATING, RETAINED, VOID, the B4 letters — are painted so the
eye finds the answer without reading the paragraph.

The more important half is that it all vanishes when nobody is watching. Colour is
decided once, from whether the stream is a terminal, with NO_COLOR honoured and
CLICOLOR_FORCE able to force it back on; when it is off the helpers return bare
text rather than a dimmer escape. `ask` output is read by pipes, by tee, and by
the agent itself reading a tool's result, and an escape sequence in any of those
is noise a later reader has to strip.

That was already happening. local.rs, bnb.rs and shard.rs emitted \x1b[2m
unconditionally, so every captured run and every jam log carried escapes in the
[local] diagnostics with no switch to turn them off. Those go through
style::dim_err now, which asks about STDERR rather than stdout — a different
question, since diagnostics and results get redirected separately. No raw escape
remains anywhere outside style.rs.

Also fixed: the header nested bold inside cyan and emitted a double reset. One
escape now, via a combined code.

Verified both ways — piped output carries zero escapes, CLICOLOR_FORCE=1 shows
the rules and the painted verdicts.
